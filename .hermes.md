# Ebonefire — Hermes Agent Project Instructions

You are the coding agent working on **Ebonefire**, a pre-alpha dark-fantasy game built with Godot 4.

## First principle: inspect before changing
- The repository may be incomplete. Inspect the current files and Git diff before making assumptions.
- Do not invent gameplay systems, story canon, assets, controls, or design decisions that the owner has not established.
- If a feature is not specified, implement only the smallest safe foundation and document the assumption.
- Preserve existing work. Never replace project files wholesale when a targeted change will do.

## Godot requirements
- Target Godot 4.x and use GDScript 2.0.
- Use Godot-native nodes, resources, signals, and scenes. Do not introduce external frameworks without a clear need.
- Use tabs for GDScript indentation, typed variables and return types where practical, and clear snake_case names.
- Prefer reusable scenes and small scripts with one responsibility.
- Use `@export` for designer-tunable values; avoid hard-coded gameplay constants when they are likely to change.
- Connect signals explicitly and disconnect only when necessary.
- Avoid deprecated Godot 3 APIs and syntax.
- Do not add plugins or asset packs without approval.

## Project structure
- `scenes/`: reusable scenes and the main scene.
- `scripts/`: shared GDScript logic.
- `assets/`: imported art, audio, fonts, and other source assets.
- `resources/`: reusable Godot resources.
- `docs/`: design notes and technical documentation.
- Keep scene-specific scripts beside their scenes when that improves ownership; update this guide if the structure changes.

## Quality and verification
- Before editing, identify the relevant scene/script and its callers.
- After GDScript changes, run the project in Godot 4 headless mode when the executable is available:
  - `godot --headless --path . --editor --quit`
  - `godot --headless --path . --quit`
- If the executable is unavailable, perform static checks and clearly say that the game was not run.
- Check the Output/debugger for parse errors, missing resources, and invalid node paths.
- Do not claim a feature works unless it has been tested.
- Keep changes focused; summarize files changed, checks run, and known limitations.

## Safety and Git
- Never commit API keys, credentials, personal data, local editor state, or machine-specific paths.
- Never read or expose secret values from environment files.
- Do not delete assets, scenes, or user data as a cleanup shortcut.
- Do not force-push, rewrite history, or change repository settings.
- Keep commits small and descriptive. Do not commit unless the owner asks.

## Current project status
- This repository started as an almost-empty pre-alpha repository.
- The starter project is a neutral Godot 4 launch scaffold, not a completed game.
- Do not assume whether the final game is 2D or 3D until existing project content or an explicit owner decision establishes it.
